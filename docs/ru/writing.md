# Вставка и замена документов

В примерах используется `avadim\Manticore\QueryBuilder\Builder as ManticoreDb` и real-time
таблица `products` с полями `title` (text), `price` (float), `info` (JSON), `categories` (MVA),
`embedding` (вектор размерности 3). Передавайте поля, которые существуют в вашей таблице.

## Выбор метода

| Операция | Флаг успеха | Первый записанный ID | Полный результат |
|---|---|---|---|
| Вставка | `insert($data, $id = 0): bool` | `insertGetId($data, $id = 0): ?int` | `insertResultSet($data, $id = 0): ResultSet` |
| Замена | `replace($data, $id = 0): bool` | `replaceGetId($data, $id = 0): ?int` | `replaceResultSet($data, $id = 0): ResultSet` |

`$data` — одна ассоциативная строка или массив таких строк. Необязательный `$id` задаёт ID
одной строки; ненулевой аргумент имеет приоритет над `id` внутри неё. Для нескольких строк
аргумент игнорируется: указывайте ID в каждой строке. Поддерживаются числовые ID.

## Вставка одного документа

```php
use avadim\Manticore\QueryBuilder\Builder as ManticoreDb;

// ID создаёт сервер.
$id = ManticoreDb::table('products')->insertGetId([
    'title' => "Телефон 'Пример'",
    'price' => 99.50,
]);

// Явный ID.
$ok = ManticoreDb::table('products')->insert([
    'id' => 100,
    'title' => 'Телефон',
    'price' => 99.50,
]);

// Другой способ передать ID одной строки.
$ok = ManticoreDb::table('products')->insert(['title' => 'Планшет'], 101);
```

Обычные строки не нужно экранировать заранее: билдер форматирует значения с учётом схемы.
Если при совпадении ID нужна замена, используйте `replace()`: обычный SQL INSERT здесь
не реализует upsert и не обещает ошибку нарушения уникальности.

## Замена документа

```php
$ok = ManticoreDb::table('products')->replace([
    'id' => 100,
    'title' => 'Новый телефон',
    'price' => 120.00,
]);
```

Билдер выполняет `REPLACE INTO ... VALUES ...`: существующий документ с этим ID заменяется,
а при отсутствии ID создаётся новый документ. Неуказанные в SQL поля получают значения
по умолчанию. Например, замена только `id` и `title` сбрасывает прежнюю `price` к значению
по умолчанию. Передавайте все значения, которые требуется сохранить.

`update()` меняет поддерживаемые атрибуты подходящих документов и не создаёт отсутствующий
документ. Метод `replace()` выполняет полную замену, а не отдельный серверный синтаксис
частичной замены `REPLACE ... SET ... WHERE id=...`. См.
[справочник REPLACE](https://manual.manticoresearch.com/Data_creation_and_modification/Updating_documents/REPLACE).

## Запись нескольких документов

```php
$result = ManticoreDb::table('products')->insertResultSet([
    ['id' => 201, 'title' => 'Первый', 'price' => 10.00],
    ['id' => 202, 'title' => 'Второй', 'price' => 20.00],
]);

if ($result->success()) {
    $ids = $result->result(); // [201, 202]
}

$ok = ManticoreDb::table('products')->replace([
    ['id' => 201, 'title' => 'Обновлённый первый', 'price' => 11.00],
    ['id' => 202, 'title' => 'Обновлённый второй', 'price' => 22.00],
]);
```

Массив строк превращается в один SQL-запрос. Это не потоковый импорт: все строки и SQL
собираются в памяти. Размер запроса должен укладываться в серверный лимит пакета.
Используйте одинаковые поля во всех строках: билдер объединяет их имена, а отсутствующее
значение форматирует как `null` с учётом типа колонки. Прежнее значение поля не сохраняется.

`result()` содержит целое число для одного возвращённого ID или массив для нескольких.
Методы `*GetId()` возвращают только первый ID массовой записи. Перед чтением ID проверяйте
успех: само значение ID не является отчётом об ошибке.

## Структурированные значения

```php
$ok = ManticoreDb::table('products')->insert([
    'title' => "Книга 'Поиск'",
    'info' => ['color' => 'red', 'storage' => 512],
    'categories' => [5, 7, 11],
    'embedding' => [0.12, 0.4, 0.8],
]);
```

JSON-объекты, MVA и векторы передаются PHP-массивами в колонки соответствующих типов.
Размерность вектора должна соответствовать схеме. Серверная проверка значений сохраняется;
массив не становится допустимым значением произвольной колонки. SQL-выражения передавайте
явно через существующий `raw()`, не подставляя пользовательский ввод в SQL.

## Ошибки и последний результат

```php
$query = ManticoreDb::table('products');
$ok = $query->insert(['title' => 'Телефон']);
$result = $query->lastResultSet();

if (!$ok) {
    $message = $result->error();
} else {
    $id = $result->result();
}
```

Ошибки выполнения записи доступны через `false`, `success()` и `error()`. Методы
`*ResultSet()` сразу возвращают полный ответ. Ошибка чтения вызывает `QueryErrorException`.
Запросы одного соединения разделяют `lastResultSet()`: он относится к последней операции,
включая служебные команды. Сохраните нужный результат до следующей команды. См.
[ResultSet](result_set.md).

Автоматического повтора записи нет. При потере соединения результат операции может быть
неизвестен, а безусловный повтор может повторить её эффект. Несколько команд автоматически
не становятся одной атомарной операцией; см. [транзакции](configuration.md).

## Необязательное ленивое получение ID (2.6)

По умолчанию после INSERT/REPLACE выполняется `SELECT LAST_INSERT_ID()`, даже если метод
возвращает `bool`. ID сохраняется в последнем результате. Первая запись в таблицу с
непрогретым кешем может также выполнить `DESCRIBE`; схема кешируется соединением.

Настройка соединения `lazy_insert_ids` откладывает получение ID для булевых методов
`insert()` и `replace()`:

```php
ManticoreDb::init([
    'host' => '127.0.0.1',
    'port' => 9306,
    'lazy_insert_ids' => true,
]);

$query = ManticoreDb::table('products');
$ok = $query->insert(['title' => 'Телефон']); // без запроса ID
$result = $query->lastResultSet();          // без запроса ID
$result->success();                        // без запроса ID
if ($ok) {
    $id = $result->result();                // SELECT LAST_INSERT_ID()
    $sameId = $result->result();            // из кеша, без SQL
}
```

Получайте отложенные ID **до любой следующей команды на том же клиенте/соединении**,
включая чтения, служебные команды, команды транзакции и произвольный SQL. Клиент
консервативно считает отложенные ID устаревшими при подготовке следующего запроса.
Устаревший результат вызывает `LogicException`, а не возвращает ID другой записи.
Команды на других соединениях не мешают. Уже загруженные ID сохраняются после последующих
команд. Сохранённый результат удерживает исходный клиент: сброс соединения не переносит
загрузку ID на новое соединение.

Если после успешной записи получение ID завершилось ошибкой, `result()` выбрасывает и
запоминает её. `success()`/`error()` продолжают описывать саму запись. Повтор записи или
скрытая повторная загрузка ID не выполняется. Результат с незагруженными ID содержит
callback и не предназначен для сериализации.

`insertGetId()`, `replaceGetId()`, `insertResultSet()` и `replaceResultSet()` всегда получают
ID сразу. Старые пользовательские клиенты сохраняют прежний путь. Наследник PDOClient должен
явно включить поддержку через `supportsDeferredInsert()` и соблюдать контракт отложенной записи.
