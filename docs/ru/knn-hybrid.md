# Расширенный KNN и гибридный поиск

[English](../knn-hybrid.md)

`knn()`, `rankerExpression()` и API гибридного поиска появились в 2.7.0.

## Расширенный числовой KNN

Метод `knn()` принимает проверяемый числовой вектор и опции поиска:

```php
$rows = ManticoreDb::table('products')
    ->where('stock', '>', 0)
    ->knn('embedding', [0.2, 0.7, 0.1], 20, [
        'ef' => 100,
        'oversampling' => 2,
        'rescore' => true,
        'early_termination' => false,
        'prefilter' => true,
    ])
    ->withKnnDistance('distance')
    ->orderByKnnDistance()
    ->select('id', 'title')
    ->get();
```

Колонка должна быть `float_vector` с KNN-индексом. Расширенные опции проверяются
на Manticore 28.6.6 с библиотекой KNN; доступность на более старых серверах отличается.
`knn()` задаёт `LIMIT`, равный положительному `k`, и заменяет прежнее KNN-условие.
Последующий `limit()` может изменить число возвращаемых строк. Старый
`whereKnn(string $column, int $k, array $vector)` сохраняет прежнее поведение.

Вектор — непустой список конечных int/float. Числовые строки, разреженные массивы,
`NaN` и бесконечности отклоняются. Размерность проверяется, если она доступна
в кеше схемы; нулевой cosine-вектор отклоняется, если метрика указана там же.
Если сведений о размерности или метрике нет, проверка передаётся серверу.
`ef` — положительный int; `oversampling`
— конечное число не меньше 1. Булевы опции принимают bool или целые 0/1.
Неизвестная опция отклоняется до выполнения запроса.

Колонка расстояния сохраняется при последующем `select()`. `orderByKnnDistance()`
принимает только порядок по возрастанию: Manticore выдаёт ближайшие документы
первыми, а сортировка по атрибутам разрешает совпадения расстояния. Для иной
сортировки кандидатов нужен явный внешний запрос. KNN `total_found` относится
к кандидатам, а не к точному общему числу релевантных документов.

## Формулы ранжирования

```php
$rows = ManticoreDb::table('products')->match('phone')
    ->rankerExpression('sum(lcs)*1000+bm25')->get();
```

`rankerExpression($formula, 'export')` использует ранкер `export`. Формула должна быть
непустой и экранируется как строковый SQL-литерал; синтаксис выражения проверяет
Manticore. Сигнатура и поведение старого `ranker(string $value)` сохранены.

См. [руководство Manticore по KNN](https://manual.manticoresearch.com/Searching/KNN?static=true).

## Гибридный поиск с RRF в PHP

```php
$query = ManticoreDb::table('products')->where('stock', '>', 0);
$result = $query->hybridSearch('phone', 'embedding', [0.2, 0.7, 0.1], [
    'text_candidates' => 200,
    'vector_candidates' => 150,
    'text_weight' => 1.5,
    'vector_weight' => 1,
    'rank_constant' => 60,
    'knn_options' => ['ef' => 200, 'prefilter' => true],
]);
$rows = $result->rows();               // список массивов документов
$first = $result->first();             // array|null
$hits = $result->hits();               // HybridHit[]
$page = $result->paginateWindow(20, 2); // data, page, per_page, window_total, total_found
```

`hybridSearch()`, `hybridGet()` и `hybridFirst()` выполняют поиск сразу. Последние
два метода возвращают массивы документов / первый документ. Общие структурные
фильтры атрибутов, включая вложенные группы, JSON и MVA, применяются к обеим ветвям.
Исходный запрос клонируется и сохраняет фильтры и опции.

Первая ветвь получает текстовые совпадения; вторая независимо ищет векторных соседей.
Документ может попасть в одну или обе ветви. Объединение выполняется в PHP по
формуле `sum(weight / (rank_constant + rank))`, ранги начинаются с 1. Это отдельный
механизм от одного запроса `match()->whereKnn()` и от серверного fusion. Вектор
передаёт приложение; этот API не вызывает провайдеров эмбеддингов.

Общий запрос выбирает все колонки и не содержит готовых MATCH/KNN, сырых SQL-условий,
JOIN, группировки, фасетов, подсветки, видимых вычисляемых полей, сортировки, limit
или offset. Текст экранируется по умолчанию; `escape => false` явно включает
нативный MATCH-синтаксис. Допустимы показанные выше опции и `escape`; неизвестные
ключи отклоняются до выполнения. Окна кандидатов — int от 1 до 10000; веса — конечные
числа от 0 до 1000000, хотя бы один вес положительный; `rank_constant` — int от 0
до 1000000. Нулевой вес отключает ветвь; пустой текст отключает текстовую ветвь.
Вектор и опции KNN должны оставаться корректными даже при отключённой векторной ветви.

У `HybridHit` доступны `id()`, `document()`, `score()`, `textRank()`, `vectorRank()`,
`textScore()` и `distance()`. Отсутствующая ветвь имеет null в своих полях и даёт
нулевой вклад. При совпадении ID поля документа берутся из текстовой ветви.
Равные итоговые оценки упорядочиваются по числовому unsigned ID по возрастанию.
ID вне диапазона int PHP возвращаются точными десятичными строками через отдельный
строковый SQL-алиас, без потери точности в PDO.

## Экспорт результата

`HybridResult::toArray()` возвращает `hits`, `window_total`, `total_found`,
`text_meta` и `vector_meta`. Каждый элемент `hits` сохраняет формат существующего
`HybridHit::toArray()`: `id`, `document`, `score`, `textRank`, `vectorRank`,
`textScore` и `distance`. Метаданные — массив, в том числе пустой, если они загружены,
либо null, если недоступны. У пустого результата `hits` пуст и размер окна равен
нулю; `total_found` всегда null. Опции поиска и повторный список документов не включены.

Оба класса реализуют `JsonSerializable` с тем же представлением:

```php
$array = $result->toArray();
$json = json_encode($result, JSON_THROW_ON_ERROR | JSON_PRESERVE_ZERO_FRACTION);
$hitJson = json_encode($result->firstHit(), JSON_THROW_ON_ERROR);
```

Экспорт не выполняет SQL и не меняет результат или `lastResultSet()`.
Типы ID соответствуют PHP API: значения больше `PHP_INT_MAX` остаются строками.
Клиент должен сохранять точность и для числовых ID. Флаги и ошибки кодирования JSON
контролирует вызывающий код; некорректный текст не заменяется молча.

## Страницы окна и выполнение

`windowTotal()` и `count($result)` считают объединённое окно кандидатов.
`totalFound()` возвращает null: общий размер объединённой выдачи неизвестен.
`textMeta()` и `vectorMeta()` дают сохранённые метаданные сервера либо null для
отсутствующей ветви. Складывать totals ветвей нельзя. `paginateWindow()` режет
только готовое окно без новых SQL; `total_found` страницы остаётся null.
Большие окна увеличивают память, трафик и работу сервера. Явный `max_matches`
должен покрывать оба заявленных окна; иначе помощник сам задаёт его на клонах.

Ветви выполняются последовательно на одном клиенте без общего snapshot. META
сохраняются до преобразования строк и вызова логгера. Ошибка ветви передаётся
вызывающему коду, даже если другая ветвь успешна. Повторов и скрытого fallback нет.
`lastResultSet()` относится к последней выполненной SQL-ветви; для объединённого
результата храните `HybridResult`. Дубли ID внутри ветви и конфликты зарезервированных
транспортных алиасов отклоняются.

`HybridResult::fuse($textResultSet, $vectorResultSet, $options)` позволяет проверять
ранжирование сохранённых выдач без обращений к базе.
