# JSON-фильтры и составные полнотекстовые условия

[English](../json-fulltext.md)

Помощники расширяют существующие JSON-атрибуты и `match()` без зависимости от Laravel.
До терминального вызова методы возвращают тот же объект запроса.

## Поиск элементов JSON-массивов

```php
$rows = ManticoreDb::table('products')
    ->whereJsonContains('info->tags', ['sale', 'new'])
    ->where(function ($where) {
        $where->whereJsonOverlaps('info->categories', [2, 3])
            ->orWhereJsonLength('info.tags', 0);
    })->get();
```

| Метод | Условие |
| --- | --- |
| `whereJsonContains($path, $candidates)` | Массив содержит все переданные значения |
| `whereJsonDoesntContain($path, $candidates)` | Хотя бы одно значение отсутствует |
| `whereJsonOverlaps($path, $candidates)` | Есть хотя бы одно переданное значение |
| `whereJsonDoesntOverlap($path, $candidates)` | Ни одного значения нет |
| `whereJsonContainsKey($path)` | Путь содержит значение, отличное от null |
| `whereJsonDoesntContainKey($path)` | Путь отсутствует или содержит JSON null |
| `whereJsonLength($path, $length)` | Нативная LENGTH пути равна числу |
| `whereJsonLength($path, $operator, $length)` | Сравнение нативной LENGTH |

У каждого метода есть вариант `orWhereJson...`; все доступны внутри вложенных групп
`where()`. Кандидат — скаляр или список строк, bool и конечных чисел. `null`, объекты,
ассоциативные и вложенные массивы кандидатов отклоняются. Пустой список для contains
недопустим; overlaps с пустым списком всегда ложен, его отрицание всегда истинно.

Проверяются элементы массива, без рекурсивного поиска по объектам. У отсутствующего
или немассивного значения нет совпадающих элементов, поэтому отрицательные проверки
membership его включают. Действуют нативные преобразования типов Manticore;
строгое равенство типов JSON-скаляров не гарантируется.

## Пути, null и длина

В этих помощниках работают простые пути `info.tags[0]` и пути со стрелками:

```php
$query->whereJsonContainsKey('info->dimensions->width');
$query->whereJsonContainsKey('info->tags[1]');
$query->whereJsonContainsKey('info->"key.with.dots"->value');
```

Разрешены строковые ключи, ключи в JSON-кавычках и неотрицательные индексы в пределах
signed int32. Пустые сегменты, wildcard и SQL-фрагменты отклоняются. Общий синтаксис
старого `where()` не меняется; присваивания JSON-путям через UPDATE не добавляются.

Manticore не различает отсутствующий путь и JSON `null`: проверка ключа исключает
оба. Ноль, false, пустая строка, пустой массив и пустой объект считаются значениями.
Если различие между отсутствием ключа и null важно, храните отдельный атрибут наличия.

Сравнения длины принимают `=`, `!=`, `<>`, `<`, `<=`, `>`, `>=` и неотрицательный
PHP integer. Отсутствующие/null-пути исключаются даже при сравнении с нулём.
Для массивов, объектов и скаляров используются правила серверной LENGTH.

Membership и длина вычисляются в скрытых выражениях SELECT: грамматика SQL WHERE
не допускает эти функции напрямую. Технические колонки удаляются из ответа,
включая `search()` и агрегатные помощники. Конфликт с выбранным полем или атрибутом
таблицы вызывает `LogicException`, чтобы пользовательские данные не потерялись.
Такие вычисляемые фильтры работают только в SELECT; UPDATE и DELETE их отклоняют.
Проверки наличия ключа можно применять к UPDATE атрибутов и DELETE.

## Составной полнотекстовый поиск

```php
$result = ManticoreDb::table('products')->where('stock', '>', 0)
    ->where(function ($where) {
        $where->whereFullText('title', 'phone')
            ->orWhereFullText(['title', 'body'], 'tablet');
    })->whereJsonContains('info.tags', 'sale')
    ->orderByDesc('_score')->limit(20)->search();
```

`whereFullText($fields, $text, $options = [])` и `orWhereFullText()` принимают простое
имя TEXT-поля или непустой список полей и непустой текст поиска. Повторные вызовы
собираются в одно выражение MATCH: AND имеет приоритет над OR, вложенные группы
сохраняют границы. Обычный путь чтения добавляет `_score`, если не вызван `withoutScore()`.

Единственная опция — `escape` типа bool, по умолчанию true. Введённый пользователем
текст экранируется от операторов Manticore, затем как SQL-значение. Для доверенного
нативного выражения используйте `['escape' => false]`: SQL-литерал всё равно
экранируется. Область полей — удобство поиска, а не ограничение доступа. Токенизация
и морфология по-прежнему задаются настройками таблицы.

Сервер не может выразить OR между MATCH и фильтром атрибутов. Помощники отклоняют
смешанные деревья с таким OR и отрицание текстовых групп. Объединяйте текстовые
альтернативы внутри отдельной группы, затем добавляйте атрибуты через AND.
Группы OR, содержащие только атрибуты, поддерживаются.

На одном запросе выбирайте один полнотекстовый API. Смешивание `match()` и
`whereFullText()` вызывает `LogicException`, включая вложенные текстовые условия.
Повторный старый `match()` / `whereMatch()` по-прежнему заменяет полное выражение.

## Формула ранжирования

```php
$rows = ManticoreDb::table('products')->whereFullText('title', 'phone')
    ->rankerExpression('sum(lcs*user_weight)')->get();
```

`rankerExpression($formula, $ranker = 'expr')` принимает `expr` или `export` и
экранирует формулу. Пустая формула, нулевой байт и другой ранкер отклоняются.
Сигнатура и поведение существующего `ranker(string $value)` сохранены.

Нужна поддержка SQL JSON/MATCH/ранкера выбранным сервером; проверенные версии
указываются в руководстве тестирования выпуска. Buddy, автоматические эмбеддинги
и внешние модели для этих помощников не требуются.
