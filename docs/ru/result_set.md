# Manticore Search Query Builder for PHP (неофициальный PHP-клиент)

## ResultSet

Объект результата одного запроса с данными, метаданными и статусом выполнения.
`search()`, `exec()`, `create()`, `drop()` и другие схемные команды возвращают его напрямую.

Составные API версии 2.7 возвращают другие объекты: `insertBatch()` / `replaceBatch()` —
[BatchResult](writing.md#потоковая-пакетная-вставка-и-замена), а `hybridSearch()` —
[HybridResult](knn-hybrid.md). Их сводные счётчики и ошибки имеют отдельные контракты;
методы ResultSet ниже относятся к результату одного запроса.

### Как получить ResultSet записи

`insert()` и `replace()` возвращают boolean успеха, `update()` и `delete()` — целое число
затронутых строк. Их ResultSet нужен отдельно, если требуются SQL, ID или детали ошибки.
Это контракты этой библиотеки, а не обещание идентичного поведения Laravel. Способа два:
оба относятся к одной записи, но могут выполняться дополнительные служебные запросы.
Примеры и ленивые ID описаны в разделе [запись документов](writing.md):

```php
// 1. метод-близнец *ResultSet()
$result = ManticoreDb::table('?products')->insertResultSet(['title' => 'Laptop']);
$result->success();     // получилось ли
$result->result();      // id вставленной строки
$result->error();       // и почему не получилось, если не получилось

// 2. либо последний ResultSet соединения — уже после скалярного вызова
if (!ManticoreDb::table('?products')->insert(['title' => 'Laptop'])) {
    $error = ManticoreDb::lastResultSet()->error();
}
```

Ошибка выполнения обычной записи сохраняется в `success()` и `error()`. Сам `false`
от `insert()`/`replace()` или `0` от `update()`/`delete()` не содержит причины; ноль не
отличает отсутствие совпадений от неудачного выполнения. Ошибки аргументов и сборки SQL
могут бросать исключения, как и ленивое получение ID после успешной записи. У методов
получения строк другой контракт ошибок выполнения — см. [Ошибки](#ошибки).

Методы обычной записи:

| команда | флаг или число | id | ResultSet |
|---|---|---|---|
| INSERT | `insert(): bool` | `insertGetId(): ?int` | `insertResultSet()` |
| REPLACE | `replace(): bool` | `replaceGetId(): ?int` | `replaceResultSet()` |
| UPDATE | `update(): int` | — | `updateResultSet()` |
| DELETE | `delete(): int` | — | `deleteResultSet()` |

Запросы одного соединения разделяют слот `lastResultSet()`. Его могут заменить публичные
операции, возвращающие или публикующие ResultSet, в том числе явный `describe()` или
`getMeta()`. Внутренний DESCRIBE схемы и автоматический SHOW META этот слот не заменяют.
Сохраните нужный результат до следующей публичной операции на соединении.

### result(): mixed
Зависит от запроса и его статуса:

* PHP-массив строк для успешного SELECT;
* boolean для CREATE, DROP, TRUNCATE, OPTIMIZE и ALTER;
* целый ID, список целых ID или null для обычных INSERT/REPLACE;
* число затронутых строк для UPDATE/DELETE;
* значение конкретной команды для остальных операций.

Перед интерпретацией значения проверяйте `success()`. Обычная запись использует PHP int
для ID; точный uint64-контракт пакетной записи на старые методы не распространяется.
Последний ResultSet пакета без получения ID содержит `true`; после успешного чтения ID —
число или список, со строками вне диапазона int PHP. Общий статус импорта и ошибки ID
проверяйте в отдельном BatchResult.

### command(): ?string
Команда запроса («SELECT», «INSERT», «SHOW TABLES» и т. п.)

### sqlQuery(): ?string
Текст SQL-запроса

### execTime(): ?float
Время выполнения на стороне клиента, измеренное билдером, а не серверное `meta()['time']`.

### error(): ?string
Текст ошибки или предупреждения последнего запроса

### success(): bool
Результат без ошибок и предупреждений

### status(): ?string
Статус последнего запроса

## Методы, специфичные для SELECT

### result(): array
PHP-массив строк. Обычная выборка одной таблицы индексируется по ID, если он выбран;
результат JOIN остаётся списком, чтобы повторяющиеся ID не теряли строки.

### columns(): array
Имена колонок

### count(): int
Серверное поле метаданных `total`. Это отличается от `Query::count()`, который выполняет
отдельный COUNT-запрос. Для подсчёта элементов полученного PHP-массива используйте `count($rows)`.

### total(): int
Серверное поле `total_found`: оценка числа совпадений, а при группировке — числа групп.
Это не обязательно точное число документов. Оба метода подсчёта возвращают 0, когда нужного
поля нет; отсутствие метаданных можно определить через `hasMeta()` или методы Meta,
возвращающие `null` для неизвестных значений.

### first(): ?array
Первая строка SELECT или null, если результат пуст.

### meta(): array
Метаданные, полученные после SQL-запроса

### hasMeta(): bool и metaObject(): Meta

Доступны начиная с 2.6.0.

`hasMeta()` сообщает, были ли загружены метаданные, включая пустой ответ SHOW META.
`meta()` по-прежнему возвращает массив. `metaObject()` предоставляет объектный доступ
только для чтения к уже загруженным значениям, без выполнения SQL:

```php
$result = ManticoreDb::table('products')->search();
$meta = $result->metaObject();
$total = $meta['total_found'];
$total = $meta->totalFound();
$returned = $meta->total();
$seconds = $meta->time();
$array = $meta->toArray();
```

`Meta` поддерживает `isset()`, `foreach` и `count()`. `count($meta)` — число полей метаданных,
а не документов. Типизированные методы возвращают `null` для отсутствующих полей; доступ
по отсутствующему ключу также возвращает `null`. Изменение и удаление полей вызывает
`LogicException`. Новые неизвестные поля сервера доступны по ключу. `total_found` — серверная
оценка; при группировке может обозначать число групп. См.
[SHOW META](https://manual.manticoresearch.com/ru/Node_info_and_management/SHOW_META).

После `getRows()` метод `hasMeta()` возвращает false, а `meta()` — пустой массив.
Существующие `count()` и `total()` по-прежнему возвращают 0 при отсутствии соответствующих
полей метаданных; это не достоверные итоги. Для числа полученных строк используйте
`count($rows)`, для серверных метаданных — отдельный `getMeta()`.
`metaObject()->totalFound()` вернёт `null`, если значение неизвестно. См.
[чтение без метаданных](searching.md#чтение-без-метаданных).

### facets(?int $key = null): array
Все наборы строк фасетов либо один набор по индексу от нуля. Отсутствующий фасет
возвращается пустым массивом.

## Результаты из готовых строк

`ResultSet::of()` и `ResultSet::empty()` создают результат без SQL:

```php
use avadim\Manticore\QueryBuilder\ResultSet;

$result = ResultSet::of([['id' => 1, 'title' => 'Телефон']], ['total_found' => 20]);
$empty = ResultSet::empty();
```

`of()` приводит строки к списку и по умолчанию заполняет `total` / `total_found` его
размером. Явно переданные метаданные имеют приоритет. У `empty()` строки пусты, итоги
равны нулю. В обоих случаях `hasMeta()` возвращает true; это данные переданного набора,
а не новый серверный подсчёт.

## Метод, специфичный для SHOW VARIABLES

### variable($name): mixed
Значение переменной

### variables(): array
Все разобранные имена и значения переменных.

## Ошибки

Запрос, у которого спросили **строки**, при ошибке выполнения бросает исключение: `get()`, `getRows()`,
`first()`, `find()`, `value()`, `pluck()`, `sole()`, `count()`, агрегаты и обходы поднимают
`avadim\Manticore\QueryBuilder\QueryErrorException`. В нём есть и сообщение сервера, и сам
отвергнутый запрос — через `sql()`. Ответ `null` или `0` было бы не отличить от пустой таблицы.

```php
try {
    $rows = ManticoreDb::table('?products')->whereRegex('title', 'galaxy')->get();
}
catch (\avadim\Manticore\QueryBuilder\QueryErrorException $e) {
    $e->getMessage();   // что сказал сервер
    $e->sql();          // какой запрос он отверг
}
```

`exec()` и `search()` сохраняют ошибки выполнения в ResultSet. Проверка аргументов
и сборка SQL всё ещё могут бросить исключение до выполнения:

```php
$result = ManticoreDb::table('?products')->whereRegex('title', 'galaxy')->exec();
if (!$result->success()) {
    $error = $result->error();
}
```

Записи устроены по тому же принципу: `insert()`, `update()`, `delete()` и `replace()` отвечают
скаляром, а полный ответ последнего запроса доступен через `lastResultSet()`.
У boolean-ответа `updateOrInsert()` есть дополнительное ограничение, описанное в
[условной записи](writing.md#upsert-и-условная-запись). Пакетные методы возвращают
собственную сводку ошибок, а `hybridSearch()` передаёт ошибку ветви вызывающему коду,
не выдавая её за успешный объединённый результат.
